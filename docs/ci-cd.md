# CI/CD

GitHub Actions and Dependabot cover four flows. They are scoped so a run only happens when it gives useful feedback.

```
feature/* ──PR──▶ develop ──(auto PR)──▶ main ──▶ Android APK ──▶ tag vX.Y.Z + GitHub Release
   │                 ▲
   └── CI            └── Dependabot (weekly)
```

## Workflows

### CI — `.github/workflows/ci.yml`

**Trigger:** pull requests targeting `develop` or `main` (`opened`, `synchronize`, `reopened`, `ready_for_review`).

| Job             | What it does                                                                                           |
| --------------- | ------------------------------------------------------------------------------------------------------ |
| `Quality`       | Branch name (Git Flow), commit messages (commitlint), `typecheck`, `lint`, `format:check`              |
| `Android build` | Bundles the JS for Android (`expo export`). If native files changed, runs `prebuild` + `assembleDebug` |
| `iOS build`     | **WIP**, disabled (`if: false`)                                                                        |

The Gradle build only runs when the PR touches files that affect the native project (`package.json`, `pnpm-lock.yaml`, `app.json`, `app.config.*`, `eas.json`, `assets/`, `plugins/`, the CI workflow) or targets `main`. Pure TypeScript changes are covered by the JS bundle step, which fails on any compile or import error in about a minute.

### Release PR — `.github/workflows/release-pr.yml`

**Trigger:** push to `develop` (i.e. every merged PR).

Runs [`.github/scripts/release-notes.sh`](../.github/scripts/release-notes.sh), which groups the commits in `develop` that are not in `main` by Conventional Commit type (features, fixes, dependencies, breaking changes…) and adds a file diff summary. It then creates the `develop → main` PR, or updates the description of the one already open.

Preview the notes locally:

```bash
git fetch origin
.github/scripts/release-notes.sh origin/main origin/develop
```

### Android Release — `.github/workflows/android-release.yml`

**Trigger:** push to `main`, or manually from the Actions tab.

Uses [react-native-deploy](https://github.com/react-native-feel/react-native-deploy) (`@react-native-feel/deploy`, CLI `rnd`). The tool is split in two files:

- `android-release.yml` orchestrates the release (steps below).
- `eas-build.yml` was generated with `rnd build:configure` and is left as generated (excluded from Prettier). It runs `expo prebuild`, `gradlew :app:assembleRelease` and uploads the APK as the `application-archive` artifact (90 days).

Steps of `android-release.yml`:

1. **Resolve version** with [`.github/scripts/next-version.sh`](../.github/scripts/next-version.sh), from the Conventional Commits since the last `v*` tag:

   | Commits since last tag                  | Bump  | Example            |
   | --------------------------------------- | ----- | ------------------ |
   | `feat!:` / `BREAKING CHANGE:` footer    | major | `1.4.2 → 2.0.0`    |
   | `feat:`                                 | minor | `1.4.2 → 1.5.0`    |
   | anything else (`fix`, `chore`, `docs`…) | patch | `1.4.2 → 1.4.3`    |
   | no previous tag                         | —     | `app.json` version |

2. **Build APK**: `rnd build --platform android --profile preview` dispatches `eas-build.yml` and waits for it. If the build fails, the job stops and nothing is tagged.
3. **Download APK** from the `EAS Build` run of the same commit.
4. **Create tag and release**: `gh release create vX.Y.Z` on the built commit, with the APK attached (`pokedex-vX.Y.Z.apk`) and release notes generated by `release-notes.sh` since the previous tag.

Runs on `main` are queued, never cancelled, so two merges in a row produce two consecutive releases.

Preview the next version locally:

```bash
git fetch --tags origin
.github/scripts/next-version.sh
```

The `preview` profile in `eas.json` produces an internal `.apk`. Without a keystore it is signed with the debug key, which is fine for testing but not for the Play Store. To sign with a release key, add these repository secrets:

| Secret                       | Value                     |
| ---------------------------- | ------------------------- |
| `EAS_ANDROID_KEYSTORE`       | Base64 of the `.keystore` |
| `EAS_ANDROID_STORE_PASSWORD` | Keystore password         |
| `EAS_ANDROID_KEY_ALIAS`      | Key alias                 |
| `EAS_ANDROID_KEY_PASSWORD`   | Key password              |

### Dependabot — `.github/dependabot.yml`

- **npm:** every Monday, one grouped PR to `develop`.
- **GitHub Actions:** monthly, one grouped PR to `develop`.

Major versions are ignored. Packages tied to the Expo SDK (`expo`, `expo-*`, `@expo/*`, `react`, `react-native`, `react-native-*`, `@types/react`, `typescript`) only receive patch updates. SDK upgrades are done by hand:

```bash
pnpm expo install expo@^<next-sdk> --fix
```

## Keeping usage low

| Decision                                                       | Why                                                                   |
| -------------------------------------------------------------- | --------------------------------------------------------------------- |
| CI runs on pull requests only, not on every branch push        | A branch without a PR does not need CI; local hooks cover it          |
| Draft PRs are skipped                                          | Mark the PR ready when it should be checked                           |
| `concurrency` with `cancel-in-progress`                        | A new push cancels the outdated run of the same PR                    |
| Markdown, `docs/` and `LICENSE` changes do not trigger CI      | They cannot break the build                                           |
| `Android build` waits for `Quality`                            | No Gradle build if lint or types already failed                       |
| Gradle only on native changes, one ABI (`x86_64`), cached      | Most PRs finish with the JS bundle; full builds stay short            |
| iOS disabled                                                   | macOS runners consume minutes at 10x the Linux rate                   |
| Android release runs only on `main` and skips docs-only merges | One build per release; the waiting job is a single cheap Linux runner |

The repository is public, so standard GitHub-hosted runners are free. These limits still keep feedback fast and the setup ready for a private repository.

## Repository settings

- **Settings → Actions → General → Workflow permissions:** enable **Allow GitHub Actions to create and approve pull requests**. The Release PR workflow needs it.
- Pull requests opened with `GITHUB_TOKEN` (the release PR) do not trigger other workflows. Its commits were already checked by CI when they reached `develop`, and the merge to `main` triggers the Android build.
- `eas-build.yml` must exist on the default branch (`main`) before it can be dispatched, so the first Android build happens after the first release is merged.
